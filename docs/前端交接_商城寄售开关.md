# 前端交接说明：商城寄售开关（resell_open）

> 日期：2026-08-14 | 给管理端前端 | 后端已上线生产（123.57.68.22），本说明只涉及**管理端设置页加一个开关控件**

---

## 一、需求

管理端 **系统设置 → 交易规则** 分组，新增一个开关：**「商城寄售开关」**

| 开关状态 | 值 | 效果 |
|----------|-----|------|
| 打开 | `"1"` | 商城正常工作（默认值） |
| 关闭 | `"0"` | C 端点击商品购买（抢购 / 寄售商品购买）一律提示 **「抢购活动已经结束」** |

- 开关优先级**最高**：关闭时无论是否在抢购时间段内、是否优先用户，C 端购买都被拦。
- 只拦「买」，不拦「寄卖提交」——用户确认此行为，无需额外处理。
- 后端拦截已上线，**C 端无需改动**。

---

## 二、前端要做的（只改管理端设置页）

在 **系统设置 → 交易规则** 表单里，参照现有「短信校验」「优惠券提现开关」等 switch 控件，新增一个：

| 字段 | 值 |
|------|-----|
| 配置 key | `resell_open` |
| 显示名称 | 商城寄售开关 |
| 控件类型 | switch（开关） |
| 分组 | 交易规则 |
| 保存值 | 开 = `"1"`，关 = `"0"`（字符串） |

保存时与同页面其他配置项**一起走同一个保存接口**（见下），不需要新的接口。

---

## 三、接口（无新增接口，沿用现有系统配置接口）

### 读取：`GET /api/v1/admin/config`

返回 `data`（全部配置键值，读 `data.resell_open`）+ `_meta`（后端维护的字段元数据，已包含该字段）：

```json
"resell_open": { "label": "商城寄售开关", "group": "交易规则", "type": "switch" }
```

> 如果设置页是**动态渲染 `_meta`** 的，开关已自动出现，前端不用动；
> 如果是写死的表单字段列表，手动加一个 switch 控件即可。

### 保存：`PUT /api/v1/admin/config`

和现有开关（如 `sms_verify`）完全一致，body 里带上：

```json
{ "resell_open": "1" }
```

---

## 四、已上线的后端行为（无需前端配合）

| C 端接口 | 开关=0 时返回 |
|----------|---------------|
| `POST /api/v1/front/flash-sale/buy`（抢购） | `{"code":2005,"msg":"抢购活动已经结束"}` |
| `POST /api/v1/front/merchandises/:id/buy`（寄售商品购买） | `{"code":2005,"msg":"抢购活动已经结束"}` |
| `POST /api/v1/front/orders/:id/resell`（寄卖提交） | 不受影响，正常放行 |

- 默认值：配置不存在时按 `1`（打开）处理，不影响现有线上行为。
- 生产库当前已写入 `resell_open=1`。
- 已在生产实测：关闭 → 两接口均返回上述提示；打开 → 恢复正常。

---

## 五、验证方法（管理端）

1. 设置页把「商城寄售开关」关掉并保存；
2. C 端（手机端）点任意商品购买 → 弹「抢购活动已经结束」；
3. 打开开关 → 购买流程恢复正常提示（如"不在抢购时间段内"等正常业务提示）。
