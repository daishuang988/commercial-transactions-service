## 二、根因分析

### 2.1 硬编码问题（3项）

三个项目、多个分支的源码中存在大量 `localhost:8080` 和 `your-server-ip` 占位符：

| 位置 | 文件数 | 示例 |
|------|:--:|------|
| 管理端 `.env.production` | 1 | `VITE_API_BASE_URL=https://your-server-ip:8080/api/v1/admin` |
| 管理端 `src/views/**/*.vue` | 12 | `const uploadAction = 'http://localhost:8080/api/v1/admin/upload'` |
| 管理端导出功能 | 6 | `window.open('http://localhost:8080/api/v1/admin/.../export')` |

**为什么测试阶段没暴露：** 本地开发时 Go 后端确实运行在 `localhost:8080`，一切正常。上线走域名 + Nginx 代理后全部失效。

### 2.2 路由遗漏

`internal/handler/front/auth.go` 的 `Captcha` 函数早已写好，但 `cmd/server/main.go` 路由表里从未注册：

```go
// 缺失：fg.GET("/captcha", front.Captcha)
```

### 2.3 前端逻辑错误

`Register.vue` 第 145 行条件写反：

```javascript
// 错误（原）：sms_verify=1（已接入）时弹窗"未接入"
if (this.smsVerify === 1) {
    showDialog({ message: '短信服务未接入' })
}

// 正确（修复后）
if (this.smsVerify !== 1) {
    showDialog({ message: '短信服务未接入' })
}
```

### 2.4 部署分支混淆

移动端 FE 仓库分 master/yanquan/xinqida/shengruida 四个分支，部署时搞混了分支，把雁泉的构建产物部署到了通瑞辰服务器上。

### 2.5 合同签名 PDF 生成链断裂 🔴

**这是典型的"本地开发环境可用，服务器不可用"问题。**

#### 2.5.1 Chromium snap AppArmor 限制（#8）

整个 PDF 生成流程：
1. Go 生成带签名的 HTML → 保存到 `upload/sign_contract/xxx_sign.html`
2. headless 浏览器 HTML → PDF → `xxx_sign.pdf`
3. pdfcpu 合并原合同 + 签名 PDF → 最终合同

问题出在步骤 2：Ubuntu 22.04 上 `apt install chromium-browser` 实际安装的是 snap 版本。snap 的 AppArmor 安全策略限制了 Chromium 的文件写入范围，`--print-to-pdf` 报告写入成功（"16708 bytes written"）但文件被 snap 沙箱重定向/丢弃，实际并不存在于目标路径。

```
# Chromium 输出：
16708 bytes written to file /opt/app/upload/sign_contract/xxx_sign.pdf

# 实际检查：
ls: cannot access '/opt/app/upload/sign_contract/xxx_sign.pdf': No such file or directory
```

由于 Go 代码未检查 `exec.Command().Run()` 的错误返回，签名 PDF 生成失败后静默跳过，pdfcpu 找不到签名页就直接复制原合同，用户看到的始终是"原件"。

**修复方案：**
- 安装 `wkhtmltopdf`（apt 原生包，无沙箱限制）替代 Chromium
- 代码优先使用 wkhtmltopdf，Chromium 作为备选
- 添加 `log.Printf` 记录每步失败原因

#### 2.5.2 服务器缺少中文字体（#9）

服务器为最小化安装，没有任何中文字体。wkhtmltopdf 生成的 PDF 中"用户签名""签署日期"等中文显示为方框（tofu）。

```
# 安装前：
$ fc-list :lang=zh
（空）

# 安装后：
$ fc-list :lang=zh
WenQuanYi Micro Hei,文泉驛微米黑,文泉驿微米黑:style=Regular
WenQuanYi Zen Hei,文泉驛正黑,文泉驿正黑:style=Regular
```

**修复方案：**
- 安装 `fonts-wqy-zenhei` + `fonts-wqy-microhei`
- CSS `font-family` 改为 `"WenQuanYi Micro Hei","Microsoft YaHei",sans-serif`（Linux 优先，Windows 兜底）

#### 2.5.3 wkhtmltopdf 忽略 CSS @page 尺寸（#10）

原合同 PDF 尺寸为 615×870pt（非标准 A4）。签名页 CSS 声明了 `@page{size:615pt 870pt}`，但 wkhtmltopdf 0.12.6 忽略该声明始终输出 A4（595×842pt），导致签名页比合同窄。

**验证过程：**
```
# CSS @page 声明 size:615pt 870pt → 实际输出仍为 A4
/MediaBox [0 0 595.000000 842.000000]

# 命令行指定 → 正确
$ wkhtmltopdf --page-width 615pt --page-height 870pt ...
/MediaBox [0 0 615.000000 870.000000]
```

**修复方案：**
- 通过 `--page-width 615pt --page-height 870pt` 命令行参数强制指定（优先级高于 CSS）

#### 2.5.4 完整修复后代码

```go
// 优先 wkhtmltopdf（轻量，无 snap AppArmor 限制）
wk := findTool("wkhtmltopdf", "/usr/bin/wkhtmltopdf", "/usr/local/bin/wkhtmltopdf")
if wk != "" {
    if err := exec.Command(wk, "--page-width", "615pt", "--page-height", "870pt",
        "--margin-top", "0", "--margin-bottom", "0",
        "--margin-left", "0", "--margin-right", "0", absHTML, absSign).Run(); err != nil {
        log.Printf("[SignContract] wkhtmltopdf 失败: %v", err)
    }
} else if browser := findBrowser(); browser != "" {
    // ...
}
```

### 2.6 C端 ESLint 构建报错（#11）

`FlashSale.vue` 中 `_countdownFired` 变量以 `_` 开头，触发 `vue/no-reserved-keys` 规则。Vue 2 内部用 `_` 前缀标识私有属性，ESLint 禁止 data 中使用以 `_` 开头的键名防止冲突。

此前没暴露是因为这个变量是最近提交 `0e8b8d4` 才引入的。

## 四、部署检查清单

**每次部署前必须确认：**

- [ ] `git branch` — 确认当前分支是否正确
- [ ] `grep -r "localhost:8080\|your-server-ip" src/ .env*` — 确认无占位符
- [ ] `cat .env.production` — 确认 API 地址为相对路径
- [ ] `GOOS=linux GOARCH=amd64` — 确认交叉编译到 Linux
- [ ] `grep "<title>" dist/index.html` — 确认标题对应正确的项目
- [ ] scp 目标 IP 确认和当前分支匹配

**服务器环境依赖：**

- [ ] `wkhtmltopdf` 已安装（`which wkhtmltopdf`）
- [ ] 中文字体已安装（`fc-list :lang=zh` 非空）
- [ ] `fonts-wqy-zenhei` `fonts-wqy-microhei` 已安装

## 六、经验教训

1. **永远不要用占位符提交代码**——`your-server-ip`、`localhost:8080` 这类必须在构建前检查替换
2. **部署前核对分支**——三个仓库 × 四个项目 = 12 种分支组合，每次部署前必须确认
3. **生产构建用相对路径**——`/api/v1/admin` 而非 `http://xxx:8080/api/v1/admin`，Nginx 代理后自然生效
4. **路由注册要验证**——写了 handler 不等于能用，必须确认路由表里有注册
5. **上线前做一次完整走查**——从注册→登录→发短信→上传图片→导出，每个功能点一遍
6. **不要假设服务器有桌面环境**——`snap` 安装的 Chromium 有 AppArmor 限制，headless 场景应使用 `wkhtmltopdf` 等专用工具
7. **外部命令必须检查错误**——`exec.Command().Run()` 返回 error 不能忽略，静默失败是线上排查的最大敌人
8. **服务器字体非标配**——最小化安装的 Linux 没有中文字体，HTML→PDF 方案必须包含字体依赖
9. **CSS 声明 ≠ 命令行参数**——wkhtmltopdf 不完全遵循 CSS `@page` 声明，页面尺寸应通过 CLI 参数指定
10. **Vue 命名规范**——`data()` 中变量名不能以 `_` 开头，ESLint `vue/no-reserved-keys` 会拦截
